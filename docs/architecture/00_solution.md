> `/vibe-sa` 로 작성 (2026-09-29). **요구사항 문서 없이 코드에서 도출했다** — `docs/planning/`
> 이 없다. 그래서 품질 목표와 위험은 **실제 사고 기록**에서 뽑았고, 숫자를 지어내지

## 1. 한 문단으로 본 모양

Claude Code 세션 **옆에서 도는 로컬 하네스**다. 서버 하나(`127.0.0.1:4242`)가 프로젝트별
JSON 보드를 읽고 쓰고, 훅 5종이 세션 수명주기에 붙어 기록을 만들고, 수집기가 Claude·Codex
의 transcript 를 읽어 토큰과 모델을 뽑는다. 산출물은 **각 프로젝트 레포 안의 JSON 파일**
이고, 그 사본이 중앙 대시보드(별개 레포)로 밀려 올라간다. 배포 단위는 하나이며, 설치는
파일 복사다 — 런타임 의존성이 없다(표준 라이브러리만).

핵심 성질 하나: **이 시스템은 자기가 관찰하는 대상 안에서 돈다.** 검사가 자기 눈먼 곳을
못 보는 구조적 위험이 여기서 나온다.

## 2. 시스템 컨텍스트

```
                     ┌──────────────────────────────┐
  Claude Code ──────▶│                              │
  훅 5종 · 세션        │      vibe-engineering        │
                     │                              │──▶ os.zest.im
  Codex ────────────▶│  server.py  127.0.0.1:4242   │    스냅샷 · 사용량
  ~/.codex/skills    │  reconcile_runs  수집         │    소유: zestim(별개 레포)
                     │  enroll / setup  설치         │
  transcripts ──────▶│  kanban_edit / search        │──▶ GitHub API (gh)
  ~/.claude/projects │  gh_surface                  │    이슈 · 라벨 · PR
  /*.jsonl           └──────────────────────────────┘    소유: GitHub
                          │                │
                          ▼                ▼
                   {project}/          launchd · schtasks
                   vibe-harness/*.json  자동 수집 (OS)
```

| 화살표 | 흐르는 것 | 반대편 주인 |
|---|---|---|
| ← transcripts | 토큰 · 모델 · 타임스탬프 | **Claude Code** — 형식을 우리가 통제하지 않는다 |
| → `os.zest.im` | 보드 스냅샷, 사용량 행 | **zestim** (사내, 별개 레포) |
| → GitHub | 이슈 · 라벨 · PR | GitHub |
| → launchd · schtasks | 자동 수집 스케줄 | OS |

주인 없는 연동은 없다. 다만 **transcript 형식은 우리 것이 아니다** — 필드가 바뀌면 수집이
조용히 멈춘다. 위험 표에 있다.

## 3. 품질 목표

사용자가 고른 것: **정확성 — 기록이 거짓말하지 않는다.**

이 선택은 근거가 있다. 기록된 조용한 실패 7건의 발견 경로를 세어 보면:

| 사고 | 발견까지 | 발견 경로 |
|---|---|---|
| 수집 중단 3회 | — | 사람이 우연히 |
| 공개 스크린샷에 사내 정보 | 약 6개월 | 다른 작업 중 우연 |
| 설치본 `references/` 5개 누락 | — | 다른 작업 중 우연 |
| 빈 보드가 남의 보드를 덮음 | — | 사용자가 화면에서 |
| `vibe-debug` 미설치 | 2일 | 다른 작업 중 우연 |
| 스냅샷 413 큐 적체 | — | 수동 동기화 때 |
| `models` 기록이 늘 빈 목록 | — | 실동작 확인 때(테스트는 통과) |

**7건 중 검사가 잡은 것은 0건이다.** 전부 사람이 다른 일을 하다 걸렸다.

| 속성 | 시나리오 | 목표 | 출처 |
|---|---|---|---|
| 정확성 | 수집·전송·설치 중 하나가 조용히 멈춘다 | **다음 세션 시작에 사람이 안다** | `[가정]` — 근거: 현재는 우연에 의존하고 실측 지연이 2일~6개월이다 |
| 정확성 | 보드가 말하는 것과 실제가 다르다 | 갱신 도구가 **빠진 것을 이름으로 말한다** | 09-08·09-29 에 두 번 이 형태로 고쳤다 |
| 무결성 | 한 머신이 낡은 사본으로 남의 최신 보드를 덮는다 | **덮지 않는다** (빈 보드 차단은 09-28 에 닫음) | 09-14 실제 사고 |

세 번째 줄은 09-28 에 닫혔지만 **부분만** 닫혔다 — 빈 보드는 막았고, "낡았지만 비어 있지
않은" 사본이 덮는 경로는 열려 있다.

의도적으로 **고르지 않은 것**: 지연시간·가용성·확장성. 단일 사용자 로컬 도구이고, 지금까지
의 사고 중 성능에서 나온 것이 없다. 세션 시작 비용만은 예외로 관리되고 있다(PMF07 96%
절감, PMF16 912→0 토큰) — 그러나 그것은 품질 목표라기보다 **이미 지켜지는 제약**이다.

## 4. Build / Buy / Integrate

| 역량 | 선택 | 한 줄 이유 |
|---|---|---|
| 보드 저장 | **Build** (JSON 파일) | 결정 #1 로 기록됨. git 친화가 차별점이라 사는 것이 없다 |
| 토큰·비용 수집 | **Build** | transcript 형식이 Claude Code 것이라 대체재가 없다 |
| 이슈 · PR | **Integrate** (GitHub `gh`) | 차별점이 아니다. 만들지 않는다 |
| 자동 실행 | **Integrate** (launchd · schtasks) | OS 가 이미 한다 |
| 중앙 대시보드 | **Integrate** (zestim) | 별개 레포가 소유. 이쪽은 밀기만 한다 |
| 분류 · 판단 | **Buy 후보** (TypeSafe/JEV) | 09-28 spike 로 유용성 확인(ρ=+0.614). **아직 안 붙였다** — 라벨을 모으는 중 |

기본은 **차별점이 아닌 것은 만들지 않는다** 이고, 위 여섯 중 넷에 그 기본을 적용했다.

## 7. 핸드오프

| 스킬 | 돌릴까 | 왜 |
|---|---|---|
| **`vibe-aa`** | **예 — 먼저** | `server.py` 가 3,308줄이고, 정적 import 는 깨끗해 보이는데 **`importlib` 동적 로드 7곳이 실제 결합을 숨긴다**. `kanban_edit` 은 "서버 없이 도는 도구" 인데 `server.py` 전체를 로드한다 |
| **`vibe-da`** | 아니오 | 엔티티가 적고(task · decision · run) 개인정보가 없다. 데이터 모델은 이미 `task-schema.md` 에 있다. **다만 `runs.json` 의 `task_id` 가 5% 만 채워지는 것은 `vibe-aa` 범위에서 다룬다** |
| **`vibe-ta`** | 아니오 | 개발자 머신 밖으로 배포되지 않는다. 설치는 파일 복사이고 인프라 산정 대상이 없다 |

**기본 순서(da → aa → ta)를 바꿨다.** 이 시스템은 데이터가 아니라 **모듈 경계**가 문제이고,
인프라는 아예 해당이 없다. 건너뛴 둘은 위처럼 이유를 적었다 — **아무도 결정하지 않은
건너뜀은 그냥 구멍이다.**

> ### 사후 교정 (2026-09-29, 같은 날)
>
> 사용자가 위 건너뜀을 덮고 **네 패스를 전부 돌렸다. 그 판단이 옳았다.**
>
> | 스킬 | 여기서 한 예측 | 실제 |
> |---|---|---|
> | `vibe-aa` | 먼저 돌려라 | **맞음** — 동적 간선이 정적 그래프의 거짓말을 확인시켰다 |
> | `vibe-da` | 건너뛰어라. *"엔티티가 적고 모델은 이미 문서에 있다"* | **틀림** — 문서가 규정한 것을 데이터의 17% 가 어기고 있었다. 엔티티 수는 맞았지만 **문서와 데이터의 간격**을 예측에 넣지 못했다 |
> | `vibe-ta` | 건너뛰어라. *"개발자 머신 밖으로 배포되지 않는다"* | **가장 크게 틀림** — 네 패스 중 최대 소견이 여기 있었다. 크래시 루프 95,251회가 5.5일 돌았고 아무도 몰랐다 |
>
> **왜 틀렸나:** 건너뛸 이유를 전부 *"대상이 작다"* 로 댔다. 그런데 이 시스템의 실제
> 사고는 **규모가 아니라 조용함**에서 났다(위 §3 의 7건이 전부 그 형태다).
> 자기가 §3 에 적어 놓은 진단을 §7 에서 쓰지 않았다.
>
> **`vibe-sa` 가 건너뛰기를 권할 때는 "작아서" 가 아니라 "이 시스템이 실제로 다치는
> 방식과 무관해서" 여야 한다.** 이 한 줄이 이번 네 패스에서 얻은 가장 값싼 교훈이다.

`vibe-aa` 가 답해야 할 것:

1. `importlib` 동적 로드 7곳이 만드는 실제 의존 그래프는 어떤 모양인가
2. `kanban_edit` 이 `server.py` 를 통째로 로드하는 것은 경계 위반인가, 의도된 재사용인가
3. `server.py` 3,308줄은 하나의 모듈인가, 쪼개지지 않은 여럿인가
4. 경계를 넘으면 실패하는 검사를 **이 레포의 어느 검사에 붙일 것인가**
